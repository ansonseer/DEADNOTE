Pathfinder 系统架构

一个把求职做成 Forward-Deployed 工作方式的 Agent 系统：先找对团队，再找对人，再通过关系链把自己送进流程。

它替换掉的玩法海投官网 → BOSS 批量投 → 等 HR 捞简历
它的玩法研究市场 → 找到业务问题的 owner → 用作品证明能解决 → 再进入招聘流程
一条设计铁律模型做判断，代码做记账。分数、排期、状态机全部由代码计算，模型只输出"特征 + 证据"。
一条安全边界系统起草，人来发送。没有任何自动发消息的代码；只记录公开的职业信息。

1 · 三层分离：判断层、记账层、呈现层

模型是概率性的，求职流程需要的是可靠的账本。所以判断和记账被硬性分开：模型的输出必须先过 JSON Schema，再进 SQLite；SQLite 里的每条判断都带来源；分数与日程只由代码产生。

2 · 11 步流水线

步骤顺序由代码写死，对应你提出的 workflow：市场扫描 → 公司筛选 → 岗位发现 → 团队研究 → 业务背景 → 找人 → 判断人脉价值 → 个性化触达 → 内推 → 跟进 → 面试。找人这一步刻意留给人：脉脉、LinkedIn、会议议程、公众号署名。

3 · 一次模型调用的解剖

系统里没有"让模型自由发挥"的调用。每个任务都有四件套：prompt、JSON Schema、mock、ingest。路由器负责选模型、追加 schema、校验、纠错重试、记账。

4 · 模型分工

研究类任务全部交给国内模型，并用它们自带的联网搜索：Kimi 的内置 $web_search、智谱的 web_search 工具。Claude 是可选项，想让它写私信只需改一行配置。所有模型 ID 以各家官网为准，配置里写明了 2026-09 的状态。

5 · 证据规则与 packet 循环

让模型"凭印象"写团队近况，得到的是看起来对的错话。研究阶段因此只有三条路，且都以 URL 为门槛。

6 · 数据模型

表的顺序就是漏斗的顺序。一个"机会"是公司 × 团队 × 岗位，岗位可以为空，因为解决方案岗的 headcount 往往不公开挂出，先找对团队再问。

7 · CRM 状态机与人脉路径

你记一笔触点，状态机负责其余：关系、路径等级、机会阶段、下一条待办。没有任何一步需要你手动改状态。

8 · Fit Score 怎么算

分数只用来排序和解释，不用来预测。每一项都能在作战卡的"评分拆解"里追溯到证据。

维度满分算法特征来自
岗位贴合 role_match30role_match/10 × 类别优先级jd_classify；无岗位时按团队方向估
团队方向 team_direction20方向系数 × (已验证 1.0 / 未验证 0.7)team_research
经历重叠 experience_overlap20overlap/10fit_assess，读 profile.yaml
进入可行性 feasibility150.7×资历/10 + 0.3×城市系数jd_classify + 城市偏好
人脉路径 path150.6×当前等级 + 0.4×可达等级people.path_level + 评估的潜力
加分+7中澳双足迹 +3 · 30 天内新信号 +2 · 已有作品 +2companies / signals / assets

分层：A1 ≥ 85 今天就发；A2 75–84 本周补齐条件；B 60–74 有余力再做；C 记录在案。

9 · 载体选型：为什么不是 Coze，也不需要 Cursor

东西它是什么在这个系统里的位置
Coze / 扣子低代码 bot 平台不用。以后可做"把日报推到飞书"的壳
Dify开源工作流 / Agent 平台第二阶段可选；会用它本身是简历信号
Cursor带 AI 的 IDE与 Claude Code 同类，二选一即可
Claude Code带文件 / 终端 / 搜索的编码 agent建造者，也是 packet 模式下的研究员
Kimi / GLM / DeepSeek API国内模型，前两者自带联网研究主力，配置即换
Claude API 工具循环 / Agent SDK自主 agent 的运行时研究阶段想完全自主时再上

结论 先把流程做对，再谈载体。现在是 Python CLI + Claude Code 当操作员 + 国内模型 API；载体是最后才需要决定的事。
