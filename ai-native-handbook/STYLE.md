# 写作规范（给每一章的作者，包括未来的 AI 作者）

**读者**：AI-native 建造者。非科班，靠 Claude / Claude Code 做事，要的不是手写代码的能力，而是三种能力：
指挥 AI（把意图变成可验证的任务）、验证 AI（知道什么证据算数）、诊断 AI（出问题时知道在哪一层、怎么修）。

**每章固定结构**（标题可以换措辞，板块不能少）：

1. `# 第 NN 章 标题` + 一行斜体"本章一句话"
2. **为什么这一章对你重要**（不超过 300 字，直接说痛点）
3. **核心机制**（本章主体，60% 篇幅。第一性原理；讲到"读者能据此预测系统行为、能出题考 AI"的程度）
4. **AI 在这里最常犯的错，以及怎么识别**（每条错误配一个可观察的症状或一个能问 AI 的问题）
5. **判断清单**（可以直接抄进 CLAUDE.md / 审查模板的问题列表）
6. **飞机上的练习**（无网络、纸上或脑内可做；附评判标准或参考答案）
7. **落地后的练习**（在 Claude Code 里动手：把系统弄坏再修好）
8. **一句话记忆钩子**

**语言**：中文为主，技术名词保留英文（HTTP、KV cache、idempotency）。直接、密度高、诚实。
不写"在当今时代""随着 AI 的发展"这类空话；不写教科书绪论；不写免责声明；不出现模型名称或"AI 生成"字样。
数字只给数量级（毫秒级 / 千级 QPS），不写会过期的产品定价、版本号、排行榜。
例子要具体到"症状长什么样、日志里会看到什么、你该问 AI 哪句话"。

**长度**：每章 6000~10000 中文字符（不含代码块）。宁深勿泛。

**交叉引用**：用"见第 NN 章"，不要重复讲别的章的内容。
